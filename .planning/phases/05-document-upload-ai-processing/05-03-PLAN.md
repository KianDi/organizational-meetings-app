### 1. Update MeetingService for Summary Storage
**What:** Add method to save AI-generated summary to database
**Files:** `MeetingManager/Services/MeetingService.swift`
**Why:** Centralize database operations in MeetingService

**Changes:**
```swift
actor MeetingService {
    // Add new method
    func updateSummary(
        meetingId: UUID,
        summary: String
    ) async throws -> Meeting {
        // Update meetings table with summary
        let dto = MeetingUpdateDTO(summary: summary)

        let response: MeetingDTO = try await supabase
            .from("meetings")
            .update(dto)
            .eq("id", value: meetingId.uuidString)
            .select()
            .single()
            .execute()
            .value

        return Meeting(from: response)
    }
}
```

**Note:** MeetingUpdateDTO already exists from 04-01, just need to ensure `summary` field is optional.

### 2. Create ProcessingState Enum
**What:** Track AI processing status for UI feedback
**Files:** `MeetingManager/Models/ProcessingState.swift`
**Why:** Users need to see when AI is working (can take 5-10 seconds)

**Implementation:**
```swift
import Foundation

/// Tracks the state of AI processing for a meeting
enum ProcessingState: Equatable {
    case idle
    case uploadingDocument
    case parsingDocument
    case generatingSummary
    case extractingTasks  // Used in 05-04
    case completed
    case failed(String)   // Error message

    var isProcessing: Bool {
        switch self {
        case .uploadingDocument, .parsingDocument, .generatingSummary, .extractingTasks:
            return true
        default:
            return false
        }
    }

    var displayText: String {
        switch self {
        case .idle:
            return ""
        case .uploadingDocument:
            return "Uploading document..."
        case .parsingDocument:
            return "Parsing document..."
        case .generatingSummary:
            return "Generating AI summary..."
        case .extractingTasks:
            return "Extracting action items..."
        case .completed:
            return "Processing complete"
        case .failed(let message):
            return "Error: \(message)"
        }
    }
}
```

### 3. Add Processing Logic to MeetingState
**What:** Orchestrate document upload → parsing → summary generation
**Files:** `MeetingManager/State/MeetingState.swift`
**Why:** Centralize the multi-step AI processing workflow

**Changes:**
```swift
@Observable
final class MeetingState {
    // Add new properties
    private(set) var processingState: ProcessingState = .idle

    // Add new dependency
    private let aiService: AIService

    // Update initializer
    init(meetingService: MeetingService = MeetingService(), aiService: AIService = AIService()) {
        self.meetingService = meetingService
        self.aiService = aiService
    }

    // Add new method
    @MainActor
    func processDocument(
        meetingId: UUID,
        documentUrl: URL
    ) async {
        processingState = .uploadingDocument

        do {
            // Step 1: Parse document
            processingState = .parsingDocument
            let documentService = DocumentService()
            let documentText = try await documentService.parseDocument(url: documentUrl)

            // Step 2: Upload to meeting
            let urlString = documentUrl.lastPathComponent
            _ = try await meetingService.uploadDocument(
                meetingId: meetingId,
                documentText: documentText,
                documentUrl: urlString
            )

            // Step 3: Generate summary
            processingState = .generatingSummary
            let summary = try await aiService.generateSummary(from: documentText)

            // Step 4: Save summary
            let updatedMeeting = try await meetingService.updateSummary(
                meetingId: meetingId,
                summary: summary
            )

            // Step 5: Update local state
            if let index = meetings.firstIndex(where: { $0.id == meetingId }) {
                meetings[index] = updatedMeeting
            }

            processingState = .completed

            // Auto-clear completed state after 2 seconds
            try? await Task.sleep(nanoseconds: 2_000_000_000)
            processingState = .idle

        } catch {
            processingState = .failed(error.localizedDescription)

            // Auto-clear error after 5 seconds
            try? await Task.sleep(nanoseconds: 5_000_000_000)
            processingState = .idle
        }
    }
}
```

struct MeetingDetailView: View {
    @State private var lastFailedDocumentUrl: URL?

    private var processingStatusView: some View {
        HStack(spacing: 12) {

                                await meetingState.processDocument(
                                    meetingId: meeting.id,
                                    documentUrl: url
                                )
                            }

                        .font(.caption)
                        .buttonStyle(.borderedProminent)
                        .tint(.blue)
                    }
                }
            }
            // ... existing success/loading states ...
        }
    }

    // Save URL on processing start
    .sheet(isPresented: $showDocumentPicker) {
        DocumentPickerView { url in
            lastFailedDocumentUrl = url

                await meetingState.processDocument(
                    meetingId: meeting.id,

## Testing Strategy

**Manual testing:**
1. Upload sample meeting document (PDF with 2-3 pages)
2. Verify processing status shows all steps:
   - "Uploading document..."
   - "Parsing document..."
   - "Generating AI summary..."
   - "Processing complete"
3. Verify summary appears in meeting detail (200-400 words)
4. Re-upload same document → verify confirmation dialog
5. Simulate API failure (invalid key) → verify error message and retry button

**Sample test documents:**
- Short meeting (1 page): verify summary captures key points
- Long meeting (5 pages): verify summary is still concise
- Empty document: verify graceful error handling
- Document with no actionable items: verify summary still generates

**Edge cases:**
- Network failure during summary generation → verify retry button works
- API rate limit (429) → verify exponential backoff retries
- Very long document (20+ pages) → verify doesn't timeout
- Processing already in progress → verify can't start second upload

## Notes

**Decisions:**
- Auto-generate summary immediately after upload (no manual trigger)
- Summary regenerates on document re-upload (can be disabled in future)
- Processing status auto-dismisses after 2 seconds (completed) or 5 seconds (error)
- Retry button available for 5 seconds after failure
- Summary displayed in meeting detail (not separate screen)

**Prompt engineering notes:**
- System prompt focuses on "concise summaries"
- Request structure: overview, decisions, topics, next steps
- Paragraph format (not bullets) for natural reading
- 200-400 word target (enforced by context, not hard limit)

**Performance considerations:**
- Summary generation takes 5-10 seconds (Claude API latency)
- Prompt caching reduces cost by 90% on repeated system prompts
- No local caching of summaries (always fetch from database)

**Future considerations (not in this plan):**
- Streaming responses for real-time summary generation
- Manual "Regenerate Summary" button (separate from re-upload)
- Summary edit capability (admin can manually adjust)
- Multiple summary styles (brief, detailed, executive)
- A/B testing different prompt templates

- Plan 05-04 will extract tasks using similar processing pipeline
- Plan 05-05 will enhance UI with task list display
