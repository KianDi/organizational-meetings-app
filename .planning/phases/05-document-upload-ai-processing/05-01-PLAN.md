# Plan 05-01: Google Docs Upload and Document Parsing

**Phase:** 5 - Document Upload & AI Processing
**Plan:** 1 of 5
**Wave:** 1 (can execute in parallel with 05-02)

## Goal

Enable organizers to upload meeting documents (Google Docs exported as PDF/text) and parse the text content for AI processing.

## Context

From research (05-RESEARCH.md):
- Use UIDocumentPickerViewController for native iOS document import
- Security-scoped resources required for file access
- Support PDF, plain text, and Google Docs formats
- PDFKit for PDF text extraction (iOS 11+)

From existing architecture:
- Meeting model has `googleDocsUrl` field (currently unused)
- Need to store uploaded document content for AI processing
- DocumentService actor will handle parsing logic

### 3. Create DocumentService Actor
**What:** Thread-safe service for document parsing with PDFKit
**Files:** `MeetingManager/Services/DocumentService.swift`
**Why:** Centralize document handling logic, follow established actor pattern

**Interface:**
```swift
actor DocumentService {
    // Extract text from document URL (supports PDF, TXT)
    func parseDocument(url: URL) async throws -> String

    // Save parsed text to meeting record
    func uploadDocumentToMeeting(meetingId: UUID, documentText: String, documentUrl: String) async throws -> Meeting
}

enum DocumentError: LocalizedError {
    case unsupportedFormat
    case emptyDocument
    case parsingFailed
    case securityScopedAccessDenied
}
```

**Implementation details:**
- Use PDFKit.PDFDocument for PDF parsing
- Handle plain text files with String(contentsOf:)
- Validate file size limits (e.g., 10MB max)
- Security-scoped resource handling:
  ```swift
  guard url.startAccessingSecurityScopedResource() else {
      throw DocumentError.securityScopedAccessDenied
  }
  defer { url.stopAccessingSecurityScopedResource() }
  ```

## Testing Strategy

**Manual testing:**
1. Create meeting as admin
2. Tap "Upload Document" button
3. Select PDF from Files app → verify text extraction
4. Select plain text file → verify content stored
5. Verify non-admin users don't see upload button
6. Try uploading 10MB+ file → verify size limit error

**Edge cases:**
- Empty PDF → should show error
- Scanned PDF with no text → should show error (no OCR in Phase 5)
- Already uploaded document → should allow re-upload (overwrites previous)

## Validation

**Success criteria:**
- [ ] Organizers can upload PDF or text documents from Files app
- [ ] Document text is extracted and stored in database
- [ ] Meeting detail shows "Document: Uploaded" after successful upload
- [ ] Non-admin members cannot upload documents
- [ ] Large files (>10MB) are rejected with clear error
- [ ] App compiles without errors
- [ ] No console warnings during upload flow

## Notes

**Decisions:**
- Store document text in PostgreSQL TEXT column (no external blob storage needed for text)
- PDFKit-based extraction (no external OCR service for now)
- 10MB file size limit to prevent database bloat
- Allow document re-upload (overwrites previous) for flexibility

**Future considerations (not in this plan):**
- OCR for scanned PDFs (Phase 7 polish)
- Google Docs API direct integration (currently using export/import)
- Document versioning (track multiple uploads)

- Plan 05-02 needs Anthropic API key configuration
