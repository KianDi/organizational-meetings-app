<task type="auto">
  <name>Task 3: Create Actor-based AuthService</name>
  <files>MeetingManager/Auth/AuthService.swift</files>
  <action>
Create AuthService actor following the research pattern (see 02-RESEARCH.md "Pattern 1: Actor-Based Authentication Service"):

```swift
import Supabase

actor AuthService {
    private let supabase: SupabaseClient
    private var currentSession: Session?

    init(supabaseClient: SupabaseClient = SupabaseConfig.shared) {
        self.supabase = supabaseClient
    }

    // Sign up with email/password
    func signUp(email: String, password: String) async throws -> User {
        let response = try await supabase.auth.signUp(
            email: email,
            password: password
        )
        currentSession = response.session

        // Map Supabase user to our User model
        return User(
            id: UUID(uuidString: response.user.id.uuidString) ?? UUID(),
            email: email,
            name: email.components(separatedBy: "@").first ?? "",
            organizationIds: [],
            createdAt: Date()
        )
    }

    // Sign in with email/password
    func signIn(email: String, password: String) async throws -> Session {
        let session = try await supabase.auth.signIn(
            email: email,
            password: password
        )
        currentSession = session
        return session
    }

    // Sign out
    func signOut() async throws {
        try await supabase.auth.signOut()
        currentSession = nil
    }

    // Get current session
    func session() async -> Session? {
        return currentSession
    }
}
```

Why Actor: Research shows actors prevent race conditions in token refresh and concurrent auth operations. This is CRITICAL for auth state management.

Do NOT store passwords locally - only tokens (which will be handled by KeychainManager in plan 02-02).
